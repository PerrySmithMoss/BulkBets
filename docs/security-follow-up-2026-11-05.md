# Security follow-up — 5 November 2026

This updates the [original remediation record](security-remediation-2026-11-04.md). The owner authorized the follow-up changes and performed the required administrator installations. No scheduled backups were configured, as requested.

## Deployed and verified

- **Restricted deployment credentials:** BulkBets and perry-infra now use separate forced-command SSH accounts without Docker-group membership, shells or forwarding. Root-owned brokers validate release arguments and execute administrator-installed deployment files. CI cannot upload arbitrary infrastructure manifests or replace those files. Both brokers rejected shell/Docker commands and completed real deployments. Both repositories' old `DEPLOY_SSH_PRIVATE_KEY` secrets have been removed.
- **Application boundary:** the application broker deploys an immutable GHCR digest and checks its revision label against the commit. This is consistency checking, not signed provenance. Migration jobs are non-root, read-only, capability-free and resource-limited; routine releases no longer receive shared database provisioning credentials. An application release still has authority over BulkBets data and application secrets.
- **Host maintenance:** effective SSH settings reject root and password login. Administrator diagnostics confirmed UFW default-deny inbound/forwarded traffic and fail2ban rules. HTTP/HTTPS host rules now allow TCP only; unused multicast name resolution is disabled. Docker is 29.9.3, Node is 24.22.2, and the completed reboot activated kernel 6.1.0-54-cloud-amd64. No reboot remains pending. All seven Swarm services have their expected 1/1 replicas.
- **Network perimeter:** IONOS firewall now permits only TCP 22, 80 and 443; unused 8443/8447 rules were removed. Bounded external TCP checks reached 22/80/443 but not 2375/2376/2377/5432/7946/8443/8447. Docker publishes only TCP 80/443. No global IPv6 address is configured. This is not a comprehensive UDP or IPv6 penetration test.
- **Infrastructure repository protection:** perry-infra was already public when inspected; its visibility was not changed. Main now requires a PR and an up-to-date `scan` check, including for administrators, and blocks force pushes/deletion. The solo-owner configuration requires zero independent PR approvals. Its production environment is restricted to main and has owner approval with self-review permitted.
- **PostgreSQL patch:** the refreshed official 17.11-bookworm image fixes the newly reported APT issue with apt/libapt 2.6.2. PostgreSQL and glibc versions are unchanged. The owner installed snapshot `3b41f4f0cdb48b1291bc3a30b81889684d73d081cd01c85b629ae92618deb66e`, then the restricted workflow deployed it. Live PostgreSQL remains UID 999 with a read-only root filesystem.
- **Dependency maintenance:** compatible web/mobile lockfile updates passed lint, type checks, web unit tests and native exports. All 33 local browser cases passed. Deployment orchestration now has 17 passing cases, including versioned SMTP rotation; the two brokers have five passing boundary tests. Hosted application validation, E2E, image scan, API deployment and frontend promotion passed.
- **Certificate maintenance:** the weekly infrastructure security workflow checks the committed public database certificates for signature, server name and at least 90 days remaining validity. The current leaf expires 6 February 2029. Renewal instructions cover versioned secrets and stable CA trust. This checks the certificate inventory, not the live private database; rotations must update that inventory.
- **Mail/domain controls:** Resend TLS is enforced and the existing sending key is restricted to `bulkbets.perrysmithmoss.com`. The published `_dmarc.bulkbets.perrysmithmoss.com` record is `v=DMARC1; p=reject; adkim=s; aspf=r`. Resend reports the domain verified with DKIM/SPF. IONOS MFA is enabled. Public registrar data shows Namecheap, transfer lock enabled and domain expiry on 10 April 2027; account-side renewal settings remain unverified.

## Open items and accepted limits

1. **SMTP credential replacement — deployed:** the previous mounted password was malformed. The owner created a domain-restricted, sending-only Resend key and reinstalled the root-owned mapping to `bulkbets_smtp_password_v2`. The live API was updated with the versioned secret while retaining its container file path. Its mounted credential passed STARTTLS certificate verification, authentication and MAIL FROM checks; the API remained healthy. No recipient or message was sent, so inbox delivery is not established. The old Resend credential was handed to the owner for retirement after this verification.
2. **BulkBets repository protection — configured:** the owner explicitly authorized publishing the repository and its history. A fresh Gitleaks scan of all 118 commits found no leaks before the visibility change. `master` now requires a PR, up-to-date `validate`/`e2e` checks and conversation resolution, including for administrators; no independent approval is required for this solo-owner repository. `production` requires successful `validate`, `e2e`, `build-and-push-image` and `deploy` checks on the target commit; both branches reject force pushes and deletion. The deployment key has moved to the Production environment, restricted to `master` with owner review (self-review allowed); the deploy job now declares that environment. GitHub secret scanning and push protection are enabled, with no open secret alerts at verification. All external contributors require approval before fork PR workflows run. No subscription was purchased.
3. **Account checks:** GitHub now confirms an authenticator app alongside its passkey and Mobile method. The owner reports saving recovery codes privately; the overdue download/print reminder is no longer shown. The owner disabled SMS fallback, and the UI now offers Add instead of showing it configured. Recovery-code contents were not inspected. Namecheap confirms TOTP MFA, available backup-code recovery, domain privacy and automatic renewal of both domain and privacy protection. The owner enabled and verified security alerts; all three categories (account access, account contacts and domain changes) are on. No recovery codes were read. Domain expiry is 10 April 2027; auto-renew being enabled does not verify the future payment will succeed. Third-party token inventories and OAuth-provider account settings were not exhaustively verified; production Google OAuth remains disabled.
4. **Shared-host deployment authority:** the old VPS `deploy` account/key remains in use by the three other applications. It is still Docker-manager/host privileged. Removing its secret from these two repositories reduces their CI authority but does not eliminate the risk from those other applications' deployment paths. Do not revoke the shared key until those consumers migrate.
5. **Remaining advisories:** the final npm audit reports zero web production-tree findings and five moderate mobile production-tree entries. Full trees contain 23 moderate/3 low web entries and 12 moderate mobile entries, mainly glob/minimatch-related tooling chains. No high/critical npm findings were reported. Forced major downgrades/overrides were not applied. The infrastructure artifact retains 47 high/3 critical Debian-package findings without available fixes, plus 25 high/1 critical Go-library findings in gosu. PostgreSQL starts directly as UID 999 and does not invoke gosu. Traefik and HAProxy have zero high/critical findings in that scan. These are scanner entries, not a count of demonstrated remotely exploitable vulnerabilities. Continue upstream monitoring and the existing gates; do not treat a passing gate as a clean full report.
6. **Recovery:** the one-off encrypted recovery copy remains on the owner's Mac. It is neither an independent off-site backup nor a scheduled backup. The owner explicitly declined scheduled backups for this portfolio project.
